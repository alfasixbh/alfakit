# Changelog

All notable changes to `alfasix/alfakit` are documented here. The npm packages (`@alfakit/*`) keep their own changelogs in `packages/*/CHANGELOG.md`, generated by Changesets.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project adheres to [Semantic Versioning](https://semver.org/).

## [Unreleased]

## [0.1.4] - 2026-10-19

### Added

- `make:alfakit-resource --nested=PostResource` links the nested resource from its parent: it generates a relation manager pointing at it (`$relatedResource`) and registers it in the parent's `getRelations()`, so the records show on the parent's pages instead of being reachable only by URL. `make:alfakit-relation-manager` gains `--related=` and `--register`.
- `alfakit:install` (and so `alfakit:setup`) builds the frontend after installing the renderer, unless a Vite dev server is running, and only lists the build as a next step when it is still needed.

### Fixed

- Starter-kit mode: a missing AlfaKit Vite entry (frontend not rebuilt after the install) now explains how to build it, like the admin panel already did.
- `--generate --nested` left the parent's foreign key in the form when the child's relationship had no return type.

## [0.1.3] - 2026-10-19

### Added

- `make:alfakit-resource --generate` and `alfakit:generate` warn when the model does not allow mass assignment of the generated form fields (the first save would fail with a `MassAssignmentException`), and the installation guide explains `$fillable`.

## [0.1.2] - 2026-10-19

### Added

- `alfakit:setup` creates the admin user you sign in with: interactively it offers `make:alfakit-user`, and `--admin-email`, `--admin-name` and `--admin-password` create it unattended (panel mode). The installation guide and quick start now explain creating your first user.

### Changed

- Route names of pages and resources with nested slugs now use dots instead of "/", so the starter kits' Wayfinder can generate them (breaking for code that refers to these names): `alfakit.{panel}.pages.helpdesk/inbox` → `alfakit.{panel}.pages.helpdesk.inbox`, `alfakit.{panel}.resources.cms/pages.index` → `alfakit.{panel}.resources.cms.pages.index`, `alfakit.{panel}.pages.settings-page/general` → `alfakit.{panel}.pages.settings-page.general`. URLs are unchanged. Use `Page::getUrl()` / `Resource::getUrl()` (or `Page::getRelativeRouteName()` / `Resource::getRouteBaseName()`) instead of hand-written names.
- `Tabs::persistTabInQueryString()` writes a readable value instead of the internal component key: the tab's `id()`, its explicit `key()`, else the slug of its label (`?tab=billing-address` instead of `?tab=tabs-0.tab-1`; repeated labels get `-2`, `-3`), like Filament. Old links with internal keys still open their tab. React, Vue and Svelte; `TabSchema` gains `queryValue`, `@alfakit/core` exports `tabQueryValue()` and `tabFromQuery()`.
- The pages written by `alfakit-forms:page` and `alfakit-helpdesk:pages` render without the app's default Inertia layout, so public forms, the contact form and the customer portal no longer show a starter kit's `AppLayout` (with the app sidebar) to guests and customers. Each page opts out itself (React `Page.layout = (page) => <>{page}</>`, Vue `defineOptions({ layout: (h, page) => page })`, Svelte `export const layout` in `<script module>`); delete that line to use the app layout again. Existing pages are kept; regenerate them with `--force`.

### Fixed

- A panel whose Vite build predates AlfaKit's entries (a starter kit's own `public/build`) now fails with a hint to run `npm run build` instead of a bare "Unable to locate file in Vite manifest"; `alfakit:doctor` tells a stale build apart from entries missing in `vite.config`, and `alfakit:install`/`alfakit:setup` say to build the frontend before opening the panel.
- `alfakit:setup --roles --users` no longer stops with `Trait "Spatie\Permission\Traits\HasRoles" not found`: packages that the wizard installs with Composer are now autoloadable in the same run (`AppEnvironment::refreshAutoloader()`).
- Generated code is Pint clean in a fresh app: the panel provider stub no longer imports an unused `StatsOverviewWidget`, `alfakit:setup --roles` joins `HasRoles` to the User model's last trait statement, and the Shield config imports its default user class.
- `ImageColumn` and `ImageEntry` without `visibility()` now treat a local disk with no public `url` (Laravel's default `local` disk) as private, like `FileUpload`, and show its files through signed URLs; images uploaded in a fresh app (`FILESYSTEM_DISK=local`) were broken links.
- Every `make:alfakit-*` generator writes sorted, used imports, so generated resources and pages pass Pint's Laravel preset (`ordered_imports`) in a fresh app; only `alfakit:generate` did before.
- `successNotificationTitle()` and `successNotification()` on a custom `Action`/`BulkAction` now send their toast after the handler runs (unless the handler sent a notification itself); only prebuilt actions showed one before, so e.g. the generated users resource's Suspend/Ban/Unsuspend actions ran silently.
- `make:alfakit-resource --generate` and `make:alfakit-form/table --generate` use the `alfakit:generate` column defaults, so casts count: array/json casts become `KeyValue` (a `Textarea` showed "[object Object]"; SQLite reports json columns as text), enum casts a `Select` with the enum options, unique columns get `unique(ignoreRecord: true)`.
- Generated resources set `$recordTitleAttribute` when the model has a title column (`name`, `title`, `label`, `email`…), so page titles and breadcrumbs read "Edit Product 1" instead of "Edit 1".
- `alfakit:setup --plugins=…` and `alfakit:add` publish a plugin's own migrations (e.g. the comments tables) when the plugin was installed from Packagist in the same run; the catalog entry was read before `composer require`, so only the fallback (no migration tag) was used.
- Vue: action modals no longer contain an extra screen-reader-only "Close" outside the close button.
- Link-style actions (the default for record actions) with an icon keep no padding in all three renderers: the button size variant's `has-[>svg]:px-*` overrode the link's `p-0` only after a later restyle (for example opening a modal), so the actions column suddenly grew and the table scrolled sideways.
- `make:alfakit-resource` for a model that does not exist says how to create it (`make:model … --migration` or `--model --migration`) instead of only "generating a default form and table"; the quick start now creates the `Post`, `Tag` and `Comment` models and tables it relies on, lists the imports its form and table use, and no longer tells you to register a discovered widget.
- Plain and native selects show the "Select an option" placeholder when empty, like searchable selects (React, Vue, Svelte); they were blank.
- The record select of `AttachAction` and `AssociateAction` is labelled with the capitalised model label ("Tag", not "tag").
- `OneTimeCodeInput` keeps every digit of a pasted or autofilled code with separators ("123 456", "12-34-56"); the input's `maxlength` cut the text before the separators were removed.
- Tabs mark the tabs that hold a field with a validation error (red label, a dot and "has errors" for screen readers), and a submit whose new errors are all in other tabs opens the first of them, in all three renderers (new `componentHasErrors()` and `tabToReveal()` in `@alfakit/core`). Errors in an inactive tab were invisible.
- `alfakit:setup --logo=…` warns in the next steps when the file doesn't exist under `public/` (the panel showed a broken image), and the Shield next step no longer starts with an orphaned "Then:".
- Running `alfakit:setup` again no longer regenerates an existing users resource (it reported "done" and asked to run migrations); it shows "already set up" unless `--force`.
- Starting or leaving an impersonation no longer counts as a sign-in in the users resource ("Last sign-in"): `Impersonation::isSwitching()` is true during those logins and the generated `RecordUserSignIn` listener skips them. Apps generated before can add `if (Impersonation::isSwitching()) { return; }` to `app/Listeners/RecordUserSignIn.php`.
- `TimePicker` no longer fails every submit with "must be a valid date": the `date` rule now applies only to pickers with a date. The forms docs give the real default stored formats (`Y-m-d H:i` / `H:i` unless `seconds()`).
- A `TextInput` without `numeric()` whose value is a number (an integer attribute of the record, or a value from `$set()`) no longer fails validation with "must be a string".
- Panel email verification: verification mails sent from a panel (sign-up, "Resend", email change) link to the panel's own verification route instead of the app's `verification.verify` route (a starter kit's page, or a "Route [verification.verify] not defined" error without one), and "Resend verification email" on the prompt no longer answers 403 (the internal endpoints ran `EnsureEmailIsVerified` for the prompt's own actions). New `Page::getPanelAuthMiddleware()` lists the panel auth middleware a page's route and its internal endpoints run.
- Fields in action modals (create/edit option forms, relation manager and table action modals) get their own DOM ids instead of repeating the ids of the page form behind them, so their labels, hints and errors point at the right input (`FormStoreOptions.idPrefix`).
- `alfakit:remove shield` takes `HasRoles` (added by `alfakit:setup --roles`) off the user model when spatie/laravel-permission is removed with it, and points at the roles field of the generated users resource; every request loading the user model failed with `Trait "Spatie\Permission\Traits\HasRoles" not found`.
- Email MFA: signing in right after setting up email codes (or after another sign-in) emails a code again; the one-per-minute resend throttle held the first challenge mail back while the page said a code was sent.
- The demo seeder written by `alfakit:setup --demo` creates verified users (`email_verified_at`, set with `forceFill()`), so the demo admin can sign in when the panel uses `->emailVerification()`.
- React: action modals no longer announce a stray second "Close" to screen readers.
- Vue: a `TextInputColumn` changed back to a value it had when the page loaded is saved again (the cell compared against the value at mount).
- Accessibility: editable `TextInputColumn` and native `SelectColumn` cells are named after their column and their validation error is tied to the control (`aria-describedby`) in all three renderers; screen readers announced unnamed inputs and never read the error.
- `ColorPicker` keeps its value left to right in right-to-left languages (`#ff0000` was shown as `ff0000#`).
- `FileUpload` shows file sizes and its size limit in the panel's language and number format (it used hard-coded English units, which also read backwards in right-to-left languages).
- Generated importers and exporters round-trip: `make:alfakit-importer --generate` resolves BelongsTo columns by the related title or key (the exporter writes the title, so imports of exported files failed with "No Category matches …"), and array/json cast columns are exported as JSON (`listAsJson()`) and decoded on import instead of being flattened to "a, b".
- Overriding a resource's `canCreate()`, `canEdit()`, `canView()`, `canDelete()` or `canDeleteAny()` now also hides and refuses the prebuilt actions, bulk actions, table record links and undo (new `Resource::authorizes()`); they only consulted policies, so the activity log plugin showed a **New activity** button whose save failed.
- `alfakit:add health` (and the setup wizard) publishes spatie/laravel-health's migrations, which its default result store needs; Refresh stored nothing and every page load logged "no such table: health_check_result_history_items". `alfakit:add ops|translation-manager|mail-templates` say how to allow access (they deny everyone until `authorize()` or their gate).
- File manager: the folder path no longer collapses under the search box when the toolbar is full; the controls wrap instead.
- Svelte: confirmation modals focus their submit button (`modalAutofocus()`), like React and Vue, and no longer announce a stray "Close" to screen readers.
- API plugin: the token form offers only full access (its default) while no resource is exposed, instead of failing with "Choose at least one ability."; `alfakit:add api` says how to expose resources.
- Forms plugin: the form and submission labels are lower case inside sentences ("New form", "Create form"), like every other resource.
- Invoices plugin: the line items table (form and invoice page) spans its whole section instead of half of it.
- Table repeaters keep fixed column widths (`width('12rem')` is also the minimum, the table scrolls sideways) and hide a FusedGroup's label in cells like field labels (React, Vue, Svelte).
- `alfakit:add forms` / `alfakit:add analytics` (and the setup wizard) publish AlfaKit's import/export migrations, which their exports need; exporting form submissions failed with "no such table: exports".
- `make:alfakit-panel` for a second panel gives it its own namespace (`App\Alfakit\{Panel}\…`) as documented and leaves out `->default()`; generators follow the namespace a panel discovers its resources in, so adding a panel no longer sends the first panel's new classes to a folder it doesn't discover.
- Teams invitations and file manager share links work in apps that use immutable dates (`Date::use(CarbonImmutable::class)`, the default of the Laravel starter kits); both type-hinted the mutable `Illuminate\Support\Carbon` and failed with a TypeError.
- An own `Dashboard` subclass (discovered from `app/Alfakit/Pages`, as the dashboards docs show) replaces the registered `Dashboard::class` on the same route; the navigation showed "Dashboard" twice.
- `alfakit:setup` and `alfakit:add` register plugins on the starter-kit panel provider again; an apostrophe in a comment of the provider ("the starter kit's dashboard") stopped the editor from finding the end of the panel chain.
- `alfakit:add mail-templates` publishes the record versions table its history uses, and `alfakit:doctor` no longer treats a page's own `getExportAction()` as AlfaKit's exporter.
- `alfakit:add` no longer publishes the migrations of an installed plugin a second time when it only registers it, which made `migrate` fail with "table already exists".
- Standalone components no longer show every toast twice in apps whose layout mounts its own sonner `<Toaster />` (the starter kits do): Alfakit's toaster gets its own id (React, Vue, Svelte).
- `make:alfakit-user` creates a verified user, so it can sign in to a panel with `->emailVerification()`.
- A panel without a dashboard opens its first navigation item; starter-kit panels with the users resource opened the hidden "Choose a new password" page.
- Starter-kit apps style the "Developed by Alfa Six" credit (`standalone.css`); the emblem filled the page width.
- A signed-in user who opens a panel's login, registration or password reset page is redirected to the panel instead of the application's home (`/dashboard` in the starter kits); the routes use the new `Http\Middleware\RedirectIfAuthenticated` instead of `guest`.
- Route names of pages and resources with nested slugs (`helpdesk/inbox`, `cms/pages`, configured registrations such as `settings-page/general`) use dots instead of "/" (`pages.helpdesk.inbox`), so the starter kits' Wayfinder generates valid TypeScript (the kit's `tsc` failed with TS1005). URLs are unchanged; code that builds such route names by hand should use `Page::getUrl()` / `Resource::getUrl()`.
- A fresh starter kit keeps passing its own checks after installing AlfaKit: the panel entry and `vite.config` inputs are written the way the kits' 80-column formatter wants them, the generated users resource passes larastan level 7, and panel providers are registered in `bootstrap/providers.php` with an import when the file imports its providers (Pint).
- Searchable selects truncate a long selected label instead of drawing it over the next field.
- Customer portals (`scopeToUser()`): saving a record on an edit page or with `EditAction` keeps the signed-in user as its owner, so a form that shows the owner column can no longer move a record into another customer's account; `make:alfakit-resource --generate` and `alfakit:generate` leave the panel's owner column out (no select listing every user of the app).
- Invoices plugin: **Record payment** prefills the balance due in the right unit; it showed and recorded a hundredth of it.
- `make:alfakit-resource --generate --nested=PostResource` no longer puts a required select of the parent (and a parent column) on the nested resource; its pages create records under the parent record in the URL.
- Record history (History slide-over) labels attributes like fields and columns ("Author", "Cover image URL") instead of "Author Id" / "Cover Image Url".
- Tenant registration forms use the tenant model, so the documented `TextInput::make('slug')->unique()` validates against the tenants table instead of failing with "no such table: slug".
- `RegisterTenant` and `EditTenantProfile` pages are never discovered as ordinary pages, so tenancy pages placed in a discovered folder (as in the docs) no longer show up on other panels.
- `make:alfakit-resource --generate` and `alfakit:generate` leave the tenant ownership column (`team_id`) out of resources on tenancy panels; records are associated with the current tenant.

- Opening a record action's modal shows the spinner only on the clicked row's button, not on the same action in every row (`isActionLoading()` / `isActionProcessing()` in `@alfakit/core`).
- Undoing the edit page's save (`$isSaveUndoable`) also puts the restored values back into the open form.
- The media library upload field lists files by their original name (the media `name` with its extension), not the random stored file name.
- Key bindings keep their order in right-to-left pages ("⌘K", not "K⌘"): every `<kbd>` is `dir="ltr"` in the three renderers.
- Without `$recordTitleAttribute`, records are titled by the model label ("Edit Post", "Delete Post") instead of their key, in pages and in every table action; new `Resource::hasRecordTitle()` keeps trees, kanban cards, workflow and AI record lists from all reading "Post".
- Tree pages on a simple (modal) resource get create and edit buttons that open the resource's form in a modal; node buttons name the node ("Delete Phones"), in all 13 languages.
- The tenant menu labels its profile and registration links with the pages' own `getLabel()` ("Team settings", "Register team"), falling back to the generic labels.
- `make:alfakit-cluster` registers the clusters directory on the panel provider (`->discoverClusters(...)`) when the panel doesn't discover clusters yet.
- `alfakit:realtime` formats `echo.ts` and the edited entry with the app's formatter; `alfakit:migrate-from-filament` counts the same constructs in a dry run as in the real run and prints the next steps (`npm install && npm run build`) in the console.
- Table groups of an enum attribute are titled with the enum's label, falling back to the headlined case name (`archived` → "Archived") for enums without `HasLabel` (they showed the raw value, "Status: archived"), and show the enum's `HasIcon` icon in its `HasColor` colour before the title (React, Vue, Svelte; `TableRecordGroupSchema` gains `icon` and `color`). `Group::make('status')->enum(Status::class)` does the same for raw stored values.
- `make:alfakit-settings-page` (settings plugin) puts the page next to the panel's own pages when the app has several panels (it wrote the admin page to `app/Alfakit/Admin/Pages`, which the admin panel does not discover), and a page named like its settings class (`GeneralSettings`) no longer crashes the app with "Cannot redeclare class": the settings class is imported under an alias.
- `alfakit:eject` registers overrides with unquoted keys when they are identifiers (`TextInput: TextInputField`), as the starter kits' formatter writes them, so `npm run check` no longer fails on `resources/js/alfakit/app.tsx`.
- `make:alfakit-resource --generate`, `alfakit:generate` and `make:alfakit-form --generate` give generated fields the column's literal database default (`Toggle::make('is_active')->default(true)`, `TextInput::make('status')->…->default('draft')`, numbers and enum values), like Filament's generator; a create form started with every toggle off and every field empty. `false` booleans, `NULL`, empty strings, expression defaults (`CURRENT_TIMESTAMP`, `now()`, sequences) and date/JSON/relationship/file columns add nothing. `ModelInspector` columns carry the parsed `default`.
- Kanban: a `KanbanPage` is titled after the board ("Tasks board", translatable `alfakit-kanban::kanban.page.title` in every plugin language) instead of repeating the resource's title ("Tasks"); its sub-navigation label follows, the breadcrumbs read "Tasks › Tasks board", and `$title` / `$navigationLabel` still win (`KanbanPage::getBoardTitle()`).
- Customer portals (`scopeToUser()`): restoring a record version keeps the record's current owner (the scoped column, or a `BelongsTo`/`MorphTo` relationship's keys) instead of writing back the owner stored in that version, so a record staff had reassigned can't be moved back into another customer's account by a restore. New `Resource::getUserOwnerAttributes()`; `restoreRecordVersion($version, except: [...])` keeps the attributes it is given.
- Page forms show the server's new state after another action changed the record (for example the CMS editor after **Publish**), unless they hold unsaved edits.
- CMS: **Save draft** after an autosave is no longer refused as an edit conflict with the editor's own draft.
- Frontend files written into an app by `make:alfakit-field|column|entry|schema-component|widget|page`, `alfakit:eject` (the copied component, its helpers and the edited `app`/`ssr` entries), `alfakit-forms:page` and `alfakit-helpdesk:pages` are formatted with the app's own formatter when it has one (`node_modules/.bin/vp fmt` with a `fmt` section in vite.config, as in the Laravel starter kits; else Oxfmt or Prettier with their config), so the kits' `npm run check` passes on them; without a formatter, or if it fails, they keep AlfaKit's style. New `alfakit.file_generation.format_frontend` option (default `true`).
- `alfakit:add tags` in an app with its own `tags` table no longer publishes Spatie's migration (which then failed on every `php artisan migrate`): it registers the plugin and explains how to give Spatie Laravel Tags its own table (documented on the Tags page).
- `alfakit:migrate-from-filament`: the migrated app boots right away (the package manifest cached before `composer remove … --no-scripts` listed the removed Filament providers: "Class BladeHeroiconsServiceProvider not found"), and pages, widgets and relation managers lose Filament's `HasForms` / `InteractsWithForms` (and table, action, infolist, schema) contracts and traits instead of keeping them with a TODO, which was fatal once Filament was removed.
- Record actions inside an `ActionGroup` name the record through the resource (`getRecordTitle()`), like ungrouped ones, in tables and page headers.
- Svelte: a quick click on a select's "+" (create option) no longer leaves the option list open over the modal; popovers close on the outside pointerdown, like in React and Vue.
- File sizes under 1 kB are pluralised and localised ("11 bytes", "11 octets") instead of "11 byte".
- The one-time-code input follows the `inputs()` design option (filled, underline) like other inputs.
- Svelte: icons and lazily loaded parts no longer cause hydration mismatches when another app on the page already loaded them; the "mounted" gate is per app, like in Vue.
- Calendar: clipped event titles keep their beginning (also Latin titles in right-to-left panels) and end with an ellipsis.
- Svelte: the schema inspector button and the impersonation banner follow a language switch.
- File-upload buttons name their file for screen readers ("Remove report.pdf", "Move report.pdf up").
- Backup, ops and file-manager sizes are formatted in the panel locale (`NumberFormat::fileSize()`), like the renderers.
- Starter-kit panels and standalone components get the calendar, tree, Kanban, chart and RichEditor column styles: they moved to a shared `components.css` imported by both `themes.css` and `standalone.css`.

## [0.1.1] - 2026-10-19

### Fixed

- `alfakit:install` creates the `notifications` table migration (the generated panel turns on database notifications), and `alfakit:setup` offers to run it; signing in to a fresh panel failed with "no such table: notifications".
- `make:alfakit-resource --soft-deletes` and `alfakit:generate --soft-deletes` on a model without `SoftDeletes` leave soft-delete support out with a warning, and `TrashedFilter` leaves the query alone on such a model; the list page failed with "Call to undefined method withoutTrashed()".
- Vue: icons and lazily loaded components no longer cause hydration mismatches when another app on the page already loaded them; the "mounted" gate is now per app.
- `alfakit:migrate-from-filament` rewrites `null =>` array keys (for example in `getTabs()`) to `'' =>`, which PHP 8.5 deprecates writing as `null`; `match` arms keep `null`.
- Package READMEs load the Alfa Six logo from absolute URLs, so it shows on Packagist, npm and the read-only split repositories.

## [0.1.0] - 2026-10-18

First public beta.

### Added (beyond Filament)

- `alfakit:optimize` caches the Vite manifest as PHP (skips decoding about 1 MB of JSON per full page load and hashing it for the Inertia version); `optimize:clear` removes it, and a new build falls back to the JSON until the next optimize. The translation-manager plugin reads its cache version once per request.
- next-page prefetch on hover/focus of the table "next" button (`prefetchTablePage()`), nav links prefetch with `cacheFor` = `PREFETCH_CACHE_FOR` (10s); prefetched pages and deferred totals are invalidated after every non-GET Inertia visit and mutating internal request (`installPrefetchInvalidation()`, wired in all three `createAlfakit`).
- Inertia once props for `alfakit.translations`, `navigation`, `endpoints`, `localization`, `commandPalette` and `theme`, each keyed by a content hash (resent when the language, permissions or configuration change). `Panel::onceProps(false)` turns it off.
- `Panel::deferNavigationBadges()`: navigation badges load with the deferred `alfakitNavigationBadges` prop; items with a badge show a placeholder and the previous page's badges stay while the next loads. Page/resource `getNavigationBadge()` is not called on the page request.
- `Table::deferTotals()`: rows render first; the count query (total, last page) and summaries load after from `POST /_alfakit/table/totals` (endpoint `tableTotals`), with placeholders in all three renderers. Paging/sorting never recount (totals keyed by `deferredTotals.key`); polled and `live()` tables stay inline; a page past the end still counts at once.
- `stickyCollisionPadding()` in `@alfakit/core` (popover collision padding that clears the sticky topbar).
- the CMS page editor's live preview opens beside the form by itself when the form's column is at least 1440 px wide (never below 1024 px) and remembers each viewer's open/closed choice (`cmsPreviewOpensOnLoad()` in `@alfakit/core`, using `cmsPreviewOpensByDefault()` / `rememberedCmsPreview()`).
- the 1,000,000-row benchmark resource in the Vue and Svelte playgrounds; `scripts/bench/big.mjs --targets=react,vue,svelte,filament`.
- Mail templates plugin in the demo (Settings > Mail templates, owner only, two seeded edited templates) and in the three playgrounds (System group); showcase clips recorded (docs/public/showcase/mail-templates).
- `Block::summary(Closure|string)` — a plain-text line after the item label (`summary` in the item schema).
- `Builder::blockActionsMenu()` — item actions (move up/down, duplicate, extra item actions, delete) in a compact "More" menu per item header.
- 1,000,000-row table benchmark (`node scripts/bench/big.mjs`): first page, page 2, page 10,000, indexed and unindexed sort, select filter and prefix search, for numbered, simple and cursor pagination in AlfaKit and Filament, with a fast `BenchBigRecordsSeeder` (1M rows in ~3 s on SQLite) and a new "Large tables" docs page (`docs/content/tables/performance.md`) on pagination, counting, deep offsets, indexes and search at scale.
- Resumable chunked uploads. Files over `alfakit.uploads.chunk_size` (5 MB) are sent in chunks by FileUpload, rich editor attachments and the file manager in all three renderers (start → chunk N → complete under `/_alfakit/uploads/chunks`), with whole-file progress, per-chunk retries, resume of the same file, assembly in a local temp file (works with S3 temporary disks), type/size validation on completion and per-user chunk directories pruned by `alfakit:prune-uploads`.
- Encrypted, user-bound upload policies (`uploadPolicy` on FileUpload, `fileAttachments.uploadPolicy` on RichEditor, `upload.policy` on the file manager) so the temporary upload endpoint enforces the component's own `maxSize()` (which may now exceed `alfakit.uploads.max_size_kb`) and accepted types.
- `uploadTemporaryFile()`, `panelUploadOptions()`, `postFormWithProgress()`, `shouldChunkUpload()` and `cancelChunkedUpload()` in `@alfakit/core`; `panel.endpoints.uploadChunks` and `panel.uploadChunkSize`.

- Rich and Markdown editors and chart widgets load on first use; main entry chunks shrink by 53% (React), 41% (Vue) and 32% (Svelte).
- Svelte resolves every Lucide icon by name and loads it on demand (`loadIcon()`).
- Accessibility: `aria-describedby`/`aria-invalid`/`aria-required` on every field (`useField().aria`, core `fieldIds`, `fieldAria`), keyboard paths for clickable rows and reordering, `aria-sort`, indeterminate select-all, named icon-only controls, accessible titles on every dialog, Alt+Arrow tag reordering, "(opens in a new tab)" hints, RTL arrow keys in the Svelte calendar; a contrast test keeps all six themes at WCAG AA.
- AI agents: `php artisan alfakit:ai` writes AlfaKit's guideline and skills for agents without Laravel Boost (`AGENTS.md`, `CLAUDE.md` + `.claude/skills`, Cursor rules, Copilot instructions) and updates only its own marked section; the docs site has an `/ai` page and Copy as Markdown buttons; a test checks that every `AlfaSix\Alfakit` import in the skills, guideline and docs exists.
- Brand: the AlfaKit identity (fox mascot, Alfa Navy, Fox Orange, Warm Cream, Montserrat and Inter) in the `alfakit` theme, the docs site (logo, favicons, manifest, social card, fonts) and the README banner; assets in `art/`.

### Changed

- `@alfakit/svelte` requires Svelte 5.29 or newer (attachments).
- The built-in delete, force-delete and restore bulk actions type-hint `Enumerable $records` (chunked selections) and check each record's policy.
- `simplePaginated()` no longer runs a count query or sends `total`.
- With tenant domains, the tenant profile page lives at `/tenant-profile`.
- Only the `Dashboard` class (or a subclass named `Dashboard`) sits at the panel root; other dashboards get `/{slug}`.
- The `alfakit` theme uses the AlfaKit brand colours and Inter/Montserrat instead of indigo and Plus Jakarta Sans. Input borders are darker in every theme, and the soft and filament primaries are deeper, to meet WCAG AA.
- Widgets and relation managers are lazy by default; HTTP tests see placeholders (`lazy: true`) on the first response.
- `readOnly()` fields ignore posted values and save the server value.
- `Panel::tenantRegistration()` and `tenantProfile()` require a concrete page class.
- Vue toast styles come from `@alfakit/vue/styles.css`.
- Disabled fields keep their server value and are no longer saved; call `->dehydrated()` to save one.
- Plain strings in notification bodies, modal descriptions, helper text and placeholder content are escaped. Pass an `Htmlable` (`HtmlString`, a view) for markup.
- `->markdown()` on columns and entries escapes raw HTML and drops unsafe links.
- List pages require the `viewAny` policy ability; relation managers are read-only on View pages and when the user can't update the owner record (`RelationManager::isReadOnly()`).
- The profile page asks for the current password to change the email address or password, and a changed email address must be verified again.
- Generated keys for layout components are derived from their position, so sections, tabs and wizards keep their state across live refreshes.

### Security

- Context tokens are bound to the user they were issued to and expire after `alfakit.token_lifetime` minutes (default 1440). Internal endpoints re-run the panel's auth middleware, restore the tenant from the token and re-check membership, and run the tenant middleware. Users without `HasTenants` can no longer open any tenant. The current panel and tenant are reset between requests (Octane).
- Uploads: temporary keys are validated (no path traversal), extensions come from the detected type, dangerous types are refused (`alfakit.uploads.blocked_mime_types`), accepted types and sizes are checked on the server, temporary files belong to their uploader, and a FileUpload only keeps stored paths it was filled with.
- Fields inside hidden sections, tabs and steps are no longer saved; hidden fields' values are not sent to the browser and posted values for them are ignored.
- Relationship options, Attach/Associate and `unique()`/`exists()` rules are scoped to the current tenant; submitted keys are checked against the options query.
- Schema refresh and select search refuse hidden or unauthorised actions and hidden fields. Actions in hidden groups and sections can't be run.
- Inline cell edits require the `update` ability and refuse hidden columns; reordering only moves records from the table's own query and checks `reorder`/`update`.
- Tables without a resource (relation managers, widgets) check the model's policy.

### Fixed

- Flash data after actions was read from `props.flash`, but Inertia 3 delivers it as `page.flash`: toasts, modal closing, "deselect after bulk action" and parent-action cancelling now read it through `pageFlash()`.
- "Select all" bulk actions now respect the table's filters, search and list tab.
- React action modals re-render after a live refresh; `FileUpload` keeps the original file name after a refresh; `Table::getModel()` no longer crashes without a query; `spa(false)` is now sent to the browser.
- `startsWith()`/`endsWith()` (and the `doesnt` variants) accept values containing commas; the table schema reports the effective sort; failed reorders show a translated toast; the panel home route is a controller, so `route:cache` works on every panel.
- Hydration mismatches (sidebar cookie, tab query, mobile check, shortcut hints); Vue no longer polls or fetches during server render; React renames HTML attribute names (`tabindex`, `readonly`) from PHP.
- React sidebar links lost their styling because the link component didn't forward `asChild` props.
- Profile, tenant registration and email-verification pages returned 500 on tenant panels.
- "Create & create another" dropped relationship data.
- Repeater `addable(false)`, `deletable(false)` and `reorderable(false)` are enforced on the server.
- `unique()`/`exists()` inside a relationship Repeater use the related table and ignore the item's own record. In relationship repeaters, `$record` in item closures is now the item's record.
- `HasDefaultTenant` now picks where the panel root and login redirect.
- `$old` in `afterStateUpdated` is the previous value.
- `in()`/`notIn()`/`requiredIf()` values containing commas; `same`, `requiredIf`, `after` and similar rules refer to sibling fields inside repeaters.
- The panel discovery cache is per panel and reset when components change (tests, Octane).
- Sorting by a nested relationship column (`post.author.name`) crashed.
- Array or malformed table query strings (`?search[]=x`) returned 500.
- Hidden columns were searchable and sortable.
- A page past the end showed an empty table instead of the last page.
- Server-side dark mode never applied; the `alfakit_appearance` cookie is no longer encrypted and `darkMode()` settings are respected.
- Inline edits reached soft-deleted rows; non-scalar cell values returned 500.
- Locale, currency and Carbon settings leaked into later requests under Octane.
- Fields no longer disable during a live refresh, and the refresh no longer overwrites server `$set` values.
- Searchable selects kept requesting labels the server couldn't resolve.
- ColorPicker always wrote hex, breaking `rgb`/`hsl` formats.
- Rich and Markdown editor images were saved as dead `blob:` URLs; they are now uploaded, moved to the attachments disk on save and rewritten to the stored URL. `minHeight` works in all renderers.
- Hints render HTML (plain strings escaped). DateTimePicker min/max and "now" follow the field timezone.
- The wizard locked on the first errored step and looped when rendered outside a form; non-native TimePickers showed a calendar; MarkdownEditor loaded Markdown as HTML; repeater collapse state didn't follow reordered items; Ctrl/Cmd+B in the editor toggled the sidebar; preview object URLs were never released; wrong translation key for the download button.
- The table filter form reset while typing, and removed filters stayed in it (Svelte).
- A record action's keyboard shortcut ran it for every row; disabled URL actions navigated; the copy button in a clickable row opened the row.
- Svelte: table search text was wiped by unrelated reloads, and notification polling stalled.
- A failed reorder left the table in reorder mode; `executeJson()` dropped `allRecords`.
- Global search showed results from older queries and hid server matches on other columns.
- Charts didn't follow theme changes, replaced default `plugins`/`scales`, and were rebuilt on every poll.
- Vue: inline multi-value text entries were invisible.
- RTL leftovers in Svelte prose styles, the Vue sidebar button and the Svelte breadcrumb chevron.
- Classes passed from PHP (`extraAttributes(['class' => '…'])`) replaced the component's own classes in React and were never generated by Tailwind, because app PHP files were not scanned. Classes are now merged, style strings are converted, and the installer's stylesheet scans `app/**/*.php`.
- Panel colours from a previously visited panel stayed applied after navigating to another panel.
- Labels and URLs: resource slugs and tenancy relationship names were built from the display label, so translating or renaming a label changed routes. They now always come from the class name in English. Generated labels share one naming helper: only a trailing `_id` is removed (`valid_identifier` was cut to "Valid"), acronyms stay capitalised ("Cover image URL"), column names like `author.name` read "Author", and sentence lower-casing no longer breaks acronyms or German nouns.
- Create, Edit and View buttons that open a resource page ran their handler instead of navigating, which tried to save an empty record. Actions with a URL are now links: the schema no longer marks them as runnable, and the action endpoint refuses to execute them.
- `DateTimePicker` converted submitted values into the display timezone instead of back to the storage timezone.
- 419 errors after logging in without a full reload: requests now send the `XSRF-TOKEN` cookie, and an expired page reloads instead of failing.
- Double clicks and repeated shortcuts no longer submit an action twice.
- `MoneyInput` is recognised as a field by the frontend (live updates, wizard errors).
- React multi-file uploads kept only the last file of a batch.
- Unsaved form input (and the unsaved-changes guard) was wiped by unrelated reloads such as table polling or relation-manager paging.
- Tables with `deferLoading()` never loaded their records.
- A collapsible aside Section crashed in React; aside sections can now collapse in Vue and Svelte too.
- Svelte: chart widgets threw on mount (reactive proxies passed to Chart.js), and repeated values (colours, nav labels, options, file names) crashed keyed lists.
- Renderer strings that were hardcoded in English (screen-reader labels, rich editor toolbar, date placeholder, password toggle) are now translatable.
