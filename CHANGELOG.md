# Changelog

All notable changes to `alfasix/alfakit` are documented here. The npm packages (`@alfakit/*`) keep their own changelogs in `packages/*/CHANGELOG.md`, generated by Changesets.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project adheres to [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Upgrading (starter kits)

- Run `php artisan alfakit:install --starter-kit --no-npm` again (with your `--panel`/`--path`) and rebuild: it makes the kit's header, password field, appearance tabs, two-factor setup and split auth layout mirror in right-to-left languages. `alfakit:upgrade` lists kit files that still need it.

### Added

- `TOPBAR_END_SLOT_CLASS` in `@alfakit/core` for custom top bars.
- CMS JSON API: `GET api/cms/page` returns the site design under `site.design` (typed `CmsPageApiResponse`), never the custom code snippets.

### Changed

- The `topbar` layout moves its navigation links into the slide-out menu below `lg` (1024px) instead of `md`; between 768 and 1023px the links had been squeezed to nothing.
- Cluster and record sub-navigation sits beside the content only when the content area is at least 42rem wide (container query); narrower, it becomes a scrolling row of links above the content, the same in React, Vue and Svelte.
- `Split::from()`, `Grid` columns and `columnSpan()`/`columnStart()` inside table records follow the record's width (`sm` 16rem, `md` 20rem, `lg` 28rem, `xl` 36rem, `2xl` 48rem) instead of the browser window, so a narrow card keeps a badge under its text.

### Fixed

- The top bar no longer makes the page scroll sideways on tablets (sidebar layout with the sidebar open, and the top navigation layout): the search field folds into an icon button while the bar is narrower than 56rem, and `Slot::TOPBAR_END` content shrinks and is clipped before the bar's buttons, also in the fullscreen layout header.
- Starter kits: `<html dir>` in the root view and the shared `alfakitDocument` prop use one direction resolved once per request, so they can never disagree; an error while resolving it is now reported instead of silently falling back to the app locale's direction.
- Starter kits: the header layout, password field, appearance tabs, two-factor setup, split auth layout and React login link mirror in right-to-left languages; the header's mobile menu opens from the end of the line and breadcrumb chevrons turn around. Customised files are skipped with a note.
- ColorPicker: an empty field shows a struck-through swatch and a `#rrggbb` placeholder instead of `#000000`; CMS Site design colors show "Default".
- CMS public pages print a single favicon: the site design's replaces the panel's.
- `CodeEntry`: the copy button no longer covers the first line of code when the code scrolls sideways, and it sits at the code's end in right-to-left panels too.

## [0.2.2] - 2026-10-27

### Upgrading from 0.2.1

- `composer update "alfasix/*"`, `npm install @alfakit/react@^0.2.2` (or `@alfakit/vue`, `@alfakit/svelte`), then `npm run build`.

### Upgrading (starter kits)

- To mirror the whole page for right-to-left languages, run `php artisan alfakit:install --starter-kit --no-npm` (with the `--panel`/`--path` you installed with), then rebuild your frontend. It adds `dir` to `<html>` in `app.blade.php`, makes the kit's sidebar dock on the right in RTL, and switches a few kit classes to logical ones; it only adds what's missing, and `alfakit:upgrade` reminds you until it's done.

### Added

- Starter kits: a right-to-left panel language (Arabic, Hebrew…) mirrors the whole page, including the app's own pages and the kit's sidebar and header. `<html dir>` follows the panel language (shared `alfakitDocument` prop, `StarterKitDocument::direction()` in the root view), and the kit's sidebar docks on the right with the new `useAlfakitDirection()` (React, Vue, Svelte). The debug and schema-inspector buttons sit at the reading end.

### Changed

- Card grids (`contentGrid()`) choose their column count from the table's own width instead of the browser window, and only use a column count once each card can be at least 15rem wide. A table beside the sidebar shows fewer, wider cards instead of narrow ones with broken words. Container keys (`'@lg' => 2`) are used as given. Record text keeps at least 15rem before the record actions wrap onto their own line.

### Fixed

- Arabic-locale money and numbers in table cells, entries, stats and summaries no longer render reordered (`$US 0.00`); new `isolationDirection()` in `@alfakit/core`.
- Arabic navigation label for Webhooks.
- Card and grid table layouts: row actions no longer cover the record's text; they sit beside it, or move under it when the card is too narrow.
- A long copyable value (such as the API reference's Base URL) wraps inside its own column, with the copy button right after it instead of on top of the next column.
- Pressing Back again while a page restored by Back was still reloading could leave the browser showing a different page than the address bar. The reload is now cancelled on the next Back or Forward.

## [0.2.0] - 2026-10-27

### Upgrading from 0.1.x

0.2 is a new minor version, so `composer update` and `npm update` don't install it until you raise your constraints:

1. Raise every `alfasix/*` package you require to `^0.2` in one command (it lists them from your `composer.json`):

   ```bash
   composer require -W $(composer show --direct --name-only "alfasix/*" | sed 's/$/:^0.2/')
   ```

   Or edit `composer.json` by hand (`"alfasix/alfakit": "^0.1.13"` → `"^0.2"`, the same for each `alfasix/alfakit-*` plugin) and run `composer update "alfasix/*" -W`.

2. In `package.json`, change `@alfakit/react` (or `@alfakit/vue`, `@alfakit/svelte`) to `"^0.2.0"`, then run `npm install`.
3. Run `php artisan alfakit:upgrade --migrations`, then `php artisan migrate`. This publishes only the migrations you don't have yet (the CMS adds `alfakit_cms_site_settings`). Don't use `vendor:publish --tag=…-migrations` for this: it copies migrations you already ran again.
4. Rebuild your frontend: `npm run build` (and restart your SSR server if you use one).

Also check:

- CMS with your own Blade root view (`->rootView('site')`): to use `customCode()`, print `{{ $alfakitCmsCode ?? '' }}` before `</head>` and `{{ $alfakitCmsBodyCode ?? '' }}` before `</body>`. AlfaKit's own root view already does.
- Custom `layout:*` components now stay mounted between pages (they receive new props on each visit), so close your own menus when the URL changes.
- Plugin `authorize()` callbacks are no longer called for guests; guests are not authorized.

### Added

- `php artisan alfakit:upgrade` lists the new migrations of AlfaKit packages you set up before, and `alfakit:upgrade --migrations` publishes only those (with fresh dates), so upgrades never copy migrations you already ran.
- CMS **Site design** (`CmsPlugin::siteDesign()`, on by default): editors set the public site's logo, browser icon, main and second colors, background and text colors, heading and text fonts (fonts.bunny.net, Arabic fonts included) and corner radius in the panel. Colors become the theme variables every block already uses, so built-in and custom blocks follow them; the text on colored buttons is picked for contrast, and the page warns when text and background are hard to read. Sent to renderers as `cms.site.design`; the logo replaces the site name in the header, and the favicon and fonts go into the head.
- CMS block **Style** section on every block: background (soft, main color, second color, dark), space above and below, show on all screens / computers only / phones only, and a link name (`#pricing`) for in-page links. Sent as `block.style` and applied on the block wrapper by `CmsBlocks` in React, Vue and Svelte (`cmsBlockAttributes()` in `@alfakit/core`).
- CMS custom CSS and code (`CmsPlugin::customCode()`, **off by default**; `true` or `fn (User $user): bool` for who may edit): CSS for every public page and HTML snippets before `</head>` / `</body>` (analytics, chat widgets), with **Code history** to restore any of the last 20 versions. Custom CSS can't `@import`, run scripts or load files from other websites (escaped forms included) and can never close its `<style>` element; snippets reach pages only through the root view, never previews, Inertia props or the JSON API.

### Fixed

- Panels: clicking a sidebar item no longer rebuilds the sidebar and top bar. The panel layout stays mounted between pages, so it keeps its scroll position and open groups and doesn't flicker; on phones the sidebar sheet closes when you move to another page. Custom `layout:*` components now stay mounted too and receive new props on each visit (close your own menus when the URL changes).
- React: icons that have loaded once appear immediately on later pages instead of flashing empty.
- Kanban: a card dropped on a column it may not enter now stays in its own column with a message, instead of being saved to the last allowed column the pointer crossed on the way (dragging Draft straight to Shipped used to save it as Confirmed). While you drag over a column it may not enter, the card shows back in its own column.
- React and Svelte starter kits and standalone components with SSR: pages no longer hydrate with a mismatch (React #418) once the SSR server has rendered a panel page. Components split out of the main bundle (Html, Tabs, date pickers, Repeater, …) and auto-registered components appear right after hydration on those pages, the same on every request; panel pages still render them on the server. Svelte's on-demand icons and lazy parts there keep their server markup until hydration, as on panel pages.
- Sliders: a single-thumb slider is named by its label again, and screen readers read its hint, helper text and error, in all three renderers.
- Accessibility: the search shortcut hint (⌘K), keyboard-shortcut keys and inactive view and list tabs reach 4.5:1 contrast in the Laravel starter kits' neutral palette (they were 4.34:1), in all three renderers and every theme.
- Docs: the ColorWheel custom field example compiles under strict TypeScript.
- Forms: saving while a file is still uploading now waits for the upload instead of saving without the file (FileUpload and rich editor attachments, React, Vue and Svelte). Custom fields can register their uploads with `form.trackUpload()`.
- Standalone forms, tables and infolists on your own pages no longer require the signed-in user to pass `canAccessPanel()`: a customer without panel access can use them, and the component's own `requiresAuthentication()` and `authorize()` decide.
- Plugin `authorize(fn (User $user) => …)` callbacks are no longer called for guests, which crashed a panel's login page when global search was on; guests are simply not authorized (Forms, Activity log, Analytics, API, Backup, File manager, Health, Teams, Webhooks).
- Backups: the queued backup job now fails (so it is retried or recorded as failed) when `backup:run` exits with an error.
- Realtime presence works on API resource records: the channel names the resource, and joining is authorised through its data source and policy (tenant checked on tenancy panels) instead of failing.
- CMS redirects now apply to old paths that match no route, such as paths outside a site served with `publicRoutes(prefix: 'site')`, keeping the query string.
- File manager: a newly created public link shows "0 downloads" instead of "undefined downloads".
- `alfakit:tenancy:check` checks relationship fields inside a relationship repeater (or relationship group) against that relationship's model, so `--strict` no longer fails on valid order-line forms. Rows are labelled by state path (`OrderResource → lines.product_id`).
- Testing: `callTableBulkAction()` with form data works; the bulk selection is sent with the modal form's refresh and wizard-step validation (it failed with 404).
- Builder and Repeater items keep the path of a `Group::statePath()` inside them when saving (it was dropped, so `style.background` was saved as `background`).
- FileUpload: the drop zone lists the accepted types by short name instead of raw MIME types: `['image/png', 'image/jpeg', 'image/webp', 'image/x-icon', 'image/vnd.microsoft.icon']` shows "PNG, JPG, WebP, ICO", and `image/*` (also from `image()`) shows "Images", translated. Other types show their `mimeTypeMap()` extension or their subtype (`application/vnd.sketchup.skp` is "SKP", `.csv` is "CSV"). The label is sent as `acceptedFileTypesLabel` in the field's schema.

## [0.1.12] - 2026-10-26

### Upgrading from 0.1.11

- Update the packages: `composer update "alfasix/*"`, `npm install @alfakit/react@latest` (or `@alfakit/vue`, `@alfakit/svelte`), `php artisan alfakit:upgrade`, `npm run build`.
- Apps set up with `alfakit:realtime`: run `php artisan alfakit:realtime` again, so Echo only connects while `realtime()` is on.

### Fixed

- Webhooks: the edit page of an endpoint that receives all events shows **All events** again, so it can be saved unchanged (it showed "Selected events" with nothing ticked and failed with "events required").
- Analytics on SQLite: a page view arriving while another is being stored is retried instead of failing with "database is locked" and being lost.
- Tenancy: records created with a `CreateAction` modal (simple resources, list page header actions) now belong to the current tenant like those of create pages, instead of failing on the tenant column or vanishing from the scoped list.
- Tables: inline-editable cells of custom `records()` rows render disabled when the table model's `update` policy needs a record; before, they looked editable and every edit answered 403.
- App auth kit: the verification prompt's **Resend** and the account page's forms answered 403 for a user whose email wasn't verified yet; their requests now need only sign-in, like the pages themselves.
- Starter kits: the app sidebar lost AlfaKit's links on app pages that render a standalone component and on the auth kit's `/account`; the hidden standalone and auth-kit panels no longer count as "another panel".
- Charts: `registerChartFormatters()` / `registerChartPlugins()` imported from `@alfakit/core` had no effect under `npm run dev`, where Vite serves a second copy of the package; the registrations are now shared by every copy.
- Stacked `ImageEntry` / `ImageColumn`: the "+N" text overlapped the last image; it now starts after it, in all three renderers.
- `make:alfakit-widget --type=custom` in a starter kit now says how to pass the component to `<AlfakitWidgets>` on the app's dashboard page, which doesn't load `resources/js/alfakit`.
- `make:alfakit-page --standalone --model=Order` printed a route without the model; it now prints `Route::get('/orders/{order}', fn (Order $order) => Alfakit::render('Orders', ['orders' => [Orders::class, ['order' => $order]]]))`.
- An action in a schema (a section, callout or empty state, such as the docs' `EmptyState` `Action::make('create')`) with the name of a page action replaced it, so the page's **Create** button ran the embedded action and saved nothing; the page's own actions now win.
- Wizards: a `submitAction(Action)` inside a form ran as a page action without the form state; it now runs as a field action, so `$get` / `$set` work, in all three renderers.
- File uploads: the preview of an image uploaded in this session (and the image editor's pencil) disappeared after any server round trip (a `live()` field, a field action); the local preview is kept until the file is saved, in all three renderers.
- Rich editor: inserting a second custom block right after the first replaced it; it is now inserted after it, in all three renderers.
- Repeaters and builders: `extraItemActions()` that run on the server now show on items added in the browser right away (evaluated with `$arguments['item']` null until the next round trip; URL actions and actions that need the item still wait for it), in all three renderers.
- Back after deleting, renaming or sharing a saved table view (or reordering columns) showed the old view tabs; those requests now mark restored pages for a reload like other changes.
- `$set('published_at', now())` (the Introduction's example) left the date picker empty: the date reached the browser as UTC ISO-8601. Dates set after the form is filled now arrive in the picker's format and the panel's timezone.
- PWA in starter kits: the "Add to Home Screen" hint, the update prompt and the notifications on/off messages went to a toaster a starter kit doesn't have; they now use AlfaKit's starter kit toaster like other notifications, in all three renderers.
- Starter kits with a registered `Dashboard` page (for customisable dashboards): **G then D** opened the panel's dashboard page; it now opens the app's dashboard (`starterKitDashboard()`).
- A custom sign-in (or other auth) page in a discovered folder was also registered as a panel page, and `/admin/login` redirected to itself; the auth page classes now opt out of discovery.
- `make:alfakit-user` with an email address that already exists stops with a message instead of a database exception.
- `alfakit:add --list <plugin>` linked to a local demo host and always to the React demo; it now links to https://demo.alfakit.dev in the app's renderer (`ALFAKIT_DEMO_URL` still overrides it).
- `alfakit:remove` then `alfakit:add` of the same plugin published its migrations a second time (and the migration failed); the reinstalled package's migrations are now recognised.
- `alfakit:migrate-from-filament` now clears the compiled Blade views, so the first `npm run build` after removing Filament no longer fails on Livewire's Blade precompiler.
- `make:alfakit-plugin` in a starter kit app now says to spread the plugin's components into `createStarterKitPage()` (`createStarterKitLayout()` in Svelte) in `resources/js/pages/Alfakit/Page.*`, not `createAlfakit()`.
- Infolists on pages ignored their `columns()` (always two columns from `lg`), so the profile page's "Set up multi-factor authentication" notice was squeezed into half the card; page infolists now follow `columns()`, in all three renderers.
- Starter kits: after switching the language (or the tenant), a sidebar link could open another page (**Pages** opened **Forms**; **Projects** kept the previous tenant, so records landed in its data). The sidebar items are now keyed by their URL, so the kit's `AlfakitNav` keeps each link with its entry; nothing to re-run.
- Packaging: the Composer packages (`alfasix/alfakit`, `alfasix/alfakit-translations` and every plugin) no longer ship their `tests/` folders, whose fixture `vite.config` files made `svelte-check` fail in apps.
- Local development: the floating debug-panel and schema-inspector buttons covered the helpdesk inbox's **Send** button; they move above the reply composer while the inbox is open.
- Calendars: dates of the previous and next month were faded to 30% opacity, which failed WCAG AA contrast; they keep the muted colour at full opacity.
- Realtime: Echo connected on every page although `realtime()` was off (starter kits through the entry's `import './alfakit/echo'`, panels because the bundler put a shared CommonJS helper in the Echo chunk, which ~100 chunks then imported). `alfakit:realtime` now writes an `echo.ts` that only connects when AlfaKit calls it, importing laravel-echo and pusher-js inside it, and starter kit and standalone entries hand it over with `configureRealtime(null, { echo })`. Run `php artisan alfakit:realtime` again to upgrade an app set up earlier (it drops the old file's `connectEcho()` call and the entry import).
- Edit pages with combined relation manager tabs: the edit-conflict banner's **Review changes** listed fields nobody changed and **Reload** didn't refill the form; the form inside the tabs is now found.
- Svelte: the second user to open a record often saw no presence avatars; the room is no longer re-joined on every page update, and a room joining a channel the page already joined takes its current members, in core for all renderers.
- `unique()` in a `ReplicateAction` form ignored the record being copied, so a copy keeping the original's value passed validation and then failed on the database index; it now gets a validation error.
- Keyboard shortcuts overlay: the **Reset** button's accessible name now contains "Reset" ("Reset the shortcut for …"), in every language pack.

## [0.1.11] - 2026-10-26

### Upgrading from 0.1.10

- Update the packages: `composer update "alfasix/*"`, `npm install @alfakit/react@latest` (or `@alfakit/vue`, `@alfakit/svelte`), `php artisan alfakit:upgrade`, `npm run build`. Nothing to re-run in starter kits.
- Starter kits with `customizableDashboards()`: register the `Dashboard` page in the panel to edit the layout on the app's `/dashboard` (see Panels › Dashboard); set `$shouldRegisterNavigation = false` on it to keep its sidebar link out.

### Fixed

- Billing: with `requiresSubscription()` on a panel without tenancy, the header components (language switcher, notifications bell, a starter kit's header data) work for users without a subscription; their endpoints were redirected to the plans page.
- Comments: the comment editor takes the full width of its modal, and comment bodies follow their own writing direction (an English comment in an Arabic panel keeps its punctuation in place).
- Forms: a masked `numeric()`/`integer()` TextInput no longer turns `maxLength()`/`minLength()` into `max`/`min` rules, so a global `TextInput::configureUsing(fn ($input) => $input->maxLength(255))` no longer refuses amounts over 255.
- Forms: a Repeater's or Builder's `default([...])` keeps its item values on create (each item field's own default used to overwrite them).
- Forms: a layout component's `schema(fn () => …)` closure no longer runs again on every walk of the schema (an action request ran it up to 19 times).
- Back after a save on an edit page (one with a second history entry, such as a wizard step or tab in the URL) reloaded the page but the form kept its old values; the restored page is now loaded fresh, so the inputs show the saved data.
- Svelte apps: `npm run dev` crashed with "Error during dependency optimization: PARSE_ERROR … @alfakit/svelte/dist/standalone.css" in every starter kit and standalone app. The package entry imported `./standalone` without naming the file, and Vite's optimizer picked `standalone.css` next to the folder; the entry now imports `./standalone/index.js`.
- Global search answered 500 and showed nothing when one result had no URL (a nested record whose parent record is gone); such results are now skipped.
- Date picker calendars: new `ui.form.previous_month` / `ui.form.next_month` strings in every language pack for the previous and next month buttons, which were announced in English ("Previous page" / "Next page") whatever the language.
- An `EditAction` with nothing to edit (no form or other modal content, no resource page to link to, no `using()` or `action()`, e.g. in a table outside a resource) showed a button that toasted "Saved" and changed nothing; it is now hidden.
- `make:alfakit-form`, `-table`, `-infolist` and `-component` wrote React's `<AlfakitComponent component={…} />` into the generated class's docblock in Vue and Svelte apps; it now uses the app's renderer syntax (`:component="…"` in Vue).
- Outside panels, `make:alfakit-field`, `-column`, `-entry` and `-schema-component` told you to register the component with `createAlfakit()`, which a standalone app doesn't have; they now print the `configureAlfakit({ components })` lines for the app's entry.
- Record history: for a record that existed before `HasRecordVersions` was added, the first change showed every field as "Before: Empty". Its first tracked update now stores a **Before the history started** version with the earlier values first (new `RecordVersion::EVENT_BASELINE`, translated in every language pack), so the change shows old → new.
- An action handler that returned a file (`response()->streamDownload()`, `response()->download()`, `Storage::download()`, Laravel Excel) opened Inertia's error dialog with the file's bytes instead of downloading it, in panels, starter kits and standalone components. The file is now kept for a moment and the browser saves it from a signed, one-time link (binary files arrive intact); the modal closes and notifications show as usual. Field actions too. New `Action::download()` for URL actions that point at a file: a plain link with the `download` attribute instead of an Inertia visit that fetched the file and discarded it; the backup plugin's Download button uses it.
- `alfakit:install --ssr` with `--starter-kit` or `--standalone` was ignored without a word; it now says that it changes nothing there and that the app's own SSR setup renders those pages.
- Standalone components: a heading beside many header actions was squeezed to zero width and its text ran under the buttons; the heading now keeps its width (up to half the row) and the actions wrap beside it, in all three renderers.
- `MoneyInput` silently changed an amount outside `minValue()`/`maxValue()` on blur (−5 became 0.00 under `minValue(0)`); the amount is now kept and the form shows the validation error, in all three renderers.
- Tables: a record link around an image column without `alt()` (e.g. a cover image as the first column) had no accessible name; the first image of the cell is now named after the column (further stacked images stay decorative), in all three renderers.
- Starter kits: a `fullscreen` app page drew AlfaKit's fullscreen header (brand, top bar slots, user menu, Exit) inside the app's own layout; it now fills the layout's content area without it (new `StarterKitFullscreenLayout`, registry key `layout:fullscreen`), in all three renderers.
- Server rendering: a chrome icon replaced with `Icons::register()` was drawn as the bundled glyph on the server and as the replacement in the browser, so hydration mismatched; the replacements now apply during the server render too.
- `@alfakit/vue` ships its source maps without `sourcesContent`: an app's Tailwind (which scans `node_modules/@alfakit/vue/dist`) read JSON-escaped classes from them and printed "Found 2 warnings while optimizing generated CSS" on every build.
- Starter kits and standalone components in dark mode: danger text (row actions such as Delete, links, messages) used the kit's dark button red, about 2:1 on the dark page; it now uses a lighter red (override with `--alfakit-danger-text`), solid danger buttons unchanged.

- Panel: stats widget `pollingInterval`; notification `iconColor` and action colours; "Load more" for database notifications; favicon updates on panel switches; badges, new-tab links and nesting for child navigation items; tenant menu item colour, new tab and POST; `Panel::getDefaultTenant()`, `hasDarkMode()`, `hasDarkModeForced()`.
- Core helpers: `formatColor`, `colorToHex`, `EditorAttachments`, `applyMask`, `transformImage`, `wallClockNow`, `createLatestRequest`, `buildChartConfig`, `mergeChartOptions`, `observeThemeChanges`, `FilterFormSync`.

### Changed

- `@alfakit/svelte` requires Svelte 5.29 or newer (attachments).
- The built-in delete, force-delete and restore bulk actions type-hint `Enumerable $records` (chunked selections) and check each record's policy.
- `simplePaginated()` no longer runs a count query or sends `total`.
- With tenant domains, the tenant profile page lives at `/tenant-profile`.
- Only the `Dashboard` class (or a subclass named `Dashboard`) sits at the panel root; other dashboards get `/{slug}`.
- The `alfakit` theme uses the AlfaKit brand colours and Inter/Montserrat instead of indigo and Plus Jakarta Sans. Input borders are darker in every theme, and the soft and filament primaries are deeper, to meet WCAG AA.
- Widgets and relation managers are lazy by default; HTTP tests see placeholders (`lazy: true`) on the first response.
- `readOnly()` fields ignore posted values and save the server value.
- `Panel::tenantRegistration()` and `tenantProfile()` require a concrete page class.
- Vue toast styles come from `@alfakit/vue/styles.css`.
- Disabled fields keep their server value and are no longer saved; call `->dehydrated()` to save one.
- Plain strings in notification bodies, modal descriptions, helper text and placeholder content are escaped. Pass an `Htmlable` (`HtmlString`, a view) for markup.
- `->markdown()` on columns and entries escapes raw HTML and drops unsafe links.
- List pages require the `viewAny` policy ability; relation managers are read-only on View pages and when the user can't update the owner record (`RelationManager::isReadOnly()`).
- The profile page asks for the current password to change the email address or password, and a changed email address must be verified again.
- Generated keys for layout components are derived from their position, so sections, tabs and wizards keep their state across live refreshes.

### Security

- Context tokens are bound to the user they were issued to and expire after `alfakit.token_lifetime` minutes (default 1440). Internal endpoints re-run the panel's auth middleware, restore the tenant from the token and re-check membership, and run the tenant middleware. Users without `HasTenants` can no longer open any tenant. The current panel and tenant are reset between requests (Octane).
- Uploads: temporary keys are validated (no path traversal), extensions come from the detected type, dangerous types are refused (`alfakit.uploads.blocked_mime_types`), accepted types and sizes are checked on the server, temporary files belong to their uploader, and a FileUpload only keeps stored paths it was filled with.
- Fields inside hidden sections, tabs and steps are no longer saved; hidden fields' values are not sent to the browser and posted values for them are ignored.
- Relationship options, Attach/Associate and `unique()`/`exists()` rules are scoped to the current tenant; submitted keys are checked against the options query.
- Schema refresh and select search refuse hidden or unauthorised actions and hidden fields. Actions in hidden groups and sections can't be run.
- Inline cell edits require the `update` ability and refuse hidden columns; reordering only moves records from the table's own query and checks `reorder`/`update`.
- Tables without a resource (relation managers, widgets) check the model's policy.

### Fixed

- Flash data after actions was read from `props.flash`, but Inertia 3 delivers it as `page.flash`: toasts, modal closing, "deselect after bulk action" and parent-action cancelling now read it through `pageFlash()`.
- "Select all" bulk actions now respect the table's filters, search and list tab.
- React action modals re-render after a live refresh; `FileUpload` keeps the original file name after a refresh; `Table::getModel()` no longer crashes without a query; `spa(false)` is now sent to the browser.
- `startsWith()`/`endsWith()` (and the `doesnt` variants) accept values containing commas; the table schema reports the effective sort; failed reorders show a translated toast; the panel home route is a controller, so `route:cache` works on every panel.
- Hydration mismatches (sidebar cookie, tab query, mobile check, shortcut hints); Vue no longer polls or fetches during server render; React renames HTML attribute names (`tabindex`, `readonly`) from PHP.
- React sidebar links lost their styling because the link component didn't forward `asChild` props.
- Profile, tenant registration and email-verification pages returned 500 on tenant panels.
- "Create & create another" dropped relationship data.
- Repeater `addable(false)`, `deletable(false)` and `reorderable(false)` are enforced on the server.
- `unique()`/`exists()` inside a relationship Repeater use the related table and ignore the item's own record. In relationship repeaters, `$record` in item closures is now the item's record.
- `HasDefaultTenant` now picks where the panel root and login redirect.
- `$old` in `afterStateUpdated` is the previous value.
- `in()`/`notIn()`/`requiredIf()` values containing commas; `same`, `requiredIf`, `after` and similar rules refer to sibling fields inside repeaters.
- The panel discovery cache is per panel and reset when components change (tests, Octane).
- Sorting by a nested relationship column (`post.author.name`) crashed.
- Array or malformed table query strings (`?search[]=x`) returned 500.
- Hidden columns were searchable and sortable.
- A page past the end showed an empty table instead of the last page.
- Server-side dark mode never applied; the `alfakit_appearance` cookie is no longer encrypted and `darkMode()` settings are respected.
- Inline edits reached soft-deleted rows; non-scalar cell values returned 500.
- Locale, currency and Carbon settings leaked into later requests under Octane.
- Fields no longer disable during a live refresh, and the refresh no longer overwrites server `$set` values.
- Searchable selects kept requesting labels the server couldn't resolve.
- ColorPicker always wrote hex, breaking `rgb`/`hsl` formats.
- Rich and Markdown editor images were saved as dead `blob:` URLs; they are now uploaded, moved to the attachments disk on save and rewritten to the stored URL. `minHeight` works in all renderers.
- Hints render HTML (plain strings escaped). DateTimePicker min/max and "now" follow the field timezone.
- The wizard locked on the first errored step and looped when rendered outside a form; non-native TimePickers showed a calendar; MarkdownEditor loaded Markdown as HTML; repeater collapse state didn't follow reordered items; Ctrl/Cmd+B in the editor toggled the sidebar; preview object URLs were never released; wrong translation key for the download button.
- The table filter form reset while typing, and removed filters stayed in it (Svelte).
- A record action's keyboard shortcut ran it for every row; disabled URL actions navigated; the copy button in a clickable row opened the row.
- Svelte: table search text was wiped by unrelated reloads, and notification polling stalled.
- A failed reorder left the table in reorder mode; `executeJson()` dropped `allRecords`.
- Global search showed results from older queries and hid server matches on other columns.
- Charts didn't follow theme changes, replaced default `plugins`/`scales`, and were rebuilt on every poll.
- Vue: inline multi-value text entries were invisible.
- RTL leftovers in Svelte prose styles, the Vue sidebar button and the Svelte breadcrumb chevron.
- Classes passed from PHP (`extraAttributes(['class' => '…'])`) replaced the component's own classes in React and were never generated by Tailwind, because app PHP files were not scanned. Classes are now merged, style strings are converted, and the installer's stylesheet scans `app/**/*.php`.
- Panel colours from a previously visited panel stayed applied after navigating to another panel.
- Labels and URLs: resource slugs and tenancy relationship names were built from the display label, so translating or renaming a label changed routes. They now always come from the class name in English. Generated labels share one naming helper: only a trailing `_id` is removed (`valid_identifier` was cut to "Valid"), acronyms stay capitalised ("Cover image URL"), column names like `author.name` read "Author", and sentence lower-casing no longer breaks acronyms or German nouns.
- Create, Edit and View buttons that open a resource page ran their handler instead of navigating, which tried to save an empty record. Actions with a URL are now links: the schema no longer marks them as runnable, and the action endpoint refuses to execute them.
- `DateTimePicker` converted submitted values into the display timezone instead of back to the storage timezone.
- 419 errors after logging in without a full reload: requests now send the `XSRF-TOKEN` cookie, and an expired page reloads instead of failing.
- Double clicks and repeated shortcuts no longer submit an action twice.
- `MoneyInput` is recognised as a field by the frontend (live updates, wizard errors).
- React multi-file uploads kept only the last file of a batch.
- Unsaved form input (and the unsaved-changes guard) was wiped by unrelated reloads such as table polling or relation-manager paging.
- Tables with `deferLoading()` never loaded their records.
- A collapsible aside Section crashed in React; aside sections can now collapse in Vue and Svelte too.
- Svelte: chart widgets threw on mount (reactive proxies passed to Chart.js), and repeated values (colours, nav labels, options, file names) crashed keyed lists.
- Renderer strings that were hardcoded in English (screen-reader labels, rich editor toolbar, date placeholder, password toggle) are now translatable.
